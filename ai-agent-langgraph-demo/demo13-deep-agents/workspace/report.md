## 1. 一句话定位（🟩 A）

DeepAgents 是一个**基于 LangChain / LangGraph 的"深度智能体"框架**，通过内置**规划、子代理与文件系统**三类机制，支撑**长程、复杂任务**的执行。

用工程语言重述：它不是新的编排引擎，也不是新的模型接入层，而是**一层"上下文工程 + 默认工具集"的 harness**——把 Claude Code、Deep Research 这类"能连续工作几十分钟"的智能体中反复验证有效的脚手架模式（先写计划、把中间产物落盘、把脏活外包给子智能体、用文件承载长期记忆）沉淀为可直接调用的通用组件。

### 与相邻概念的分层关系（🟨 B）

```
┌──────────────────────────────────────────────┐
│  DeepAgents  =  harness 层（默认提示词+工具+中间件）│  ← 决定"智能体有多聪明"
├──────────────────────────────────────────────┤
│  LangChain 1.x = agent 抽象 + middleware 机制       │  ← 决定"怎么写"
├──────────────────────────────────────────────┤
│  LangGraph   = 低层编排运行时（状态图/持久化/checkpoint）│  ← 决定"怎么跑、能否恢复"
└──────────────────────────────────────────────┘
```

关键判断：**DeepAgents 与 LangGraph 不是竞品而是上下游**。需要完全自定义状态机、跨团队复用工作流时直接写 LangGraph；需要"一个能干复杂活的通用智能体"时用 DeepAgents，它 `create_deep_agent(...)` 返回的正是一个编译好的 LangGraph 对象，因此天然继承 LangGraph 的持久化、流式、断点恢复与 LangSmith 可观测能力。

## 2. 四大核心能力（🟩 A 级框架 + 🟨 B 级实现细节）

检索确认的四大能力为：**规划与任务分解、上下文管理、子代理生成、长期记忆**。以下逐项拆解其工程实现。

### 2.1 规划与任务分解：把"计划"变成一等公民

- **机制**：内置规划工具（惯例命名 `write_todos`），维护一张随执行更新的待办清单，通常存放在图状态中而非仅存在于对话文本里。
- **为什么有效**：长程任务失败的首要原因不是"不会做"，而是"做到第 20 步时忘了第 3 步的约束"。显式计划起到三重作用：① 强制模型在动手前把任务拆成可验证单元；② 作为**外部化的注意力锚点**，每轮把目标重新拉回上下文窗口近端；③ 向用户暴露进度，使中途纠偏成为可能。
- **实践要点**：规划工具的价值与"是否强制更新状态"绑定。若模型只写一次计划就不再更新，该能力退化为一次性 CoT。选型时应确认框架支持**计划模式（只读规划→用户批准→执行）**与逐项状态回填。

### 2.2 上下文管理：文件系统即"外部记忆 + 分页器"

这是 DeepAgents 相对薄 harness 最实质的差异点，也是**上下文工程（context engineering）**的落地形式。

- **文件工具集**（🟨 B）：`ls` / `read_file` / `write_file` / `edit_file`，部分版本另有 `glob` / `grep`。
- **可插拔后端**（🟨 B）：同一套文件 API 可路由到不同存储实现——
  | 后端 | 生命周期 | 典型用途 |
  |---|---|---|
  | State（图状态内虚拟 FS） | 单次运行 | 默认值，零配置、隔离安全 |
  | Filesystem（真实磁盘） | 本机持久 | 编码类智能体、需要真实读写项目 |
  | Store（LangGraph store） | **跨会话/跨线程** | 长期记忆的物理载体 |
  | Composite（按路径前缀路由） | 混合 | `/memories/` 走 store、`/workspace/` 走磁盘 |
  并配套**路径级读写权限**，限制智能体可触达的范围。
- **两种省 token 的手法**（🟨 B）：
  1. **上下文卸载（offloading）**：把超长的工具返回、检索原文、中间产物写进文件，上下文里只留路径与摘要；需要时按行区间重读。这是把"上下文窗口"当作 L1 缓存、文件系统当作 L2 存储。
  2. **自动摘要/压缩**：接近窗口上限时由中间件折叠早期对话，保留决策与约束、丢弃原始工具噪声。
- **成本侧配套**（🟨 B）：DeepAgents 的系统提示词刻意写得**长且稳定**（约两千 token 量级，覆盖能力说明、工具用法、"先想清楚再动手/澄清用户意图"的工作准则）。长度本身不是目的，**前缀稳定**才是——它让 Anthropic/OpenAI 的 prompt caching 能命中这段固定前缀，从而把"详细提示词"的边际成本压到可接受区间。这是"详细系统提示词"与"上下文管理"两条能力在成本维度上的耦合点。

### 2.3 子代理生成：上下文隔离的任务委派

- **机制**（🟨 B）：主智能体通过委派工具（惯例命名 `task`）按声明式配置（`name` / `description` / `system_prompt` / `tools` / `model`）派生子智能体。
- **本质是上下文隔离，不是并行**：子智能体拥有**干净的独立窗口**，看不到主对话历史；主智能体也看不到子智能体的推理与原始工具输出，**只收一份蒸馏后的结论**。这带来三点收益：
  1. **防污染**：高噪声探索（读十个文件、跑三次失败命令）不会灌进主上下文；
  2. **可分模型**：子任务用便宜/快的模型，主任务用强模型，是主要的降本杠杆；
  3. **可分权限**：只读型子代理与高权限执行型子代理分离，缩小爆炸半径。
- **常见反模式**（🟨 B + 工程判断）：把"需要共享大量隐式约束"的工作交给子代理——子代理没有主对话上下文，委派描述（description 字段）写得含糊，就会得到一份看似合理实则跑偏的结论。**委派质量取决于任务描述是否自包含**。
- **演进方向**（🟨 B）：由同步阻塞委派扩展到异步/后台运行的子代理，以支撑真正并行的长时任务。

### 2.4 长期记忆：把"记住"实现为"读写文件"

- **机制**（🟨 B）：以约定路径下的持久文件（如 `AGENTS.md` / `MEMORY.md` 风格）承载跨会话记忆，启动时载入上下文，运行中由模型自行追加/修订；底层通常落在 Store 后端上。
- **与 2.2 的关系**：长期记忆不是独立魔法，而是**文件系统能力在时间维度上的延伸**。这也是"四大能力"彼此咬合的地方——记忆需要落盘（文件系统）、需要被结构化维护（规划）、需要低成本载入（提示词缓存）。
- **选型提醒**：文件式记忆胜在**透明、可 diff、可人工编辑、可版本化**，弱在**检索粒度粗**（要么整份载入、要么靠模型主动去读）。若记忆规模增长到数十 KB 以上，需要额外引入向量检索或分层索引，不能指望"写进文件"自动等于"能被想起来"。

## 3. 架构与 API 速览（🟨 B 级，需核验）

以下为 DeepAgents 的惯用形态，**签名与参数名请以官方仓库为准**：

```python
from deepagents import create_deep_agent

agent = create_deep_agent(
    model="anthropic:claude-...",   # 模型无关，可换任意 provider
    tools=[search, my_tool],         # 自定义工具，与内置工具合并
    system_prompt=...,               # 追加/覆盖内置的详细提示词
    subagents=[{"name": "researcher", "description": ...,
                "system_prompt": ..., "tools": [...]}],
    skills=[...],                    # 技能目录（SKILL.md，渐进式披露）
    memory=[...],                    # 持久记忆文件路径
    backend=...,                     # 文件系统后端（state/磁盘/store/组合）
    interrupt_on={...},              # 指定工具的人工审批/编辑
    debug=True,
)
result = agent.invoke({"messages": [...]})   # 即普通 LangGraph 调用
```

**中间件栈**是理解 DeepAgents 的关键抽象（🟨 B）：上述每项能力都是一个可插拔中间件，按序包裹在模型调用前后——规划（todo）、文件系统、子代理、摘要压缩、记忆、技能、人工审批（HITL）。这意味着**能力可逐项关闭或替换**：若你的任务很短，关掉规划与子代理即可退化为一个薄 ReAct 智能体，避免为不需要的脚手架付 token。

**周边生态**（🟨 B）：MCP 工具经 LangChain 的 MCP 适配器接入；人工审批走 LangGraph 的 `interrupt`；可观测与部署复用 LangSmith / LangGraph Platform；另有面向终端使用的 CLI 形态。

## 4. 与同类方案的定位对比

| 维度 | 薄 ReAct / LangChain agent | **DeepAgents** | LangGraph（裸用） | Claude Code | OpenAI Deep Research |
|---|---|---|---|---|---|
| 抽象层级 | 低 | **中（harness）** | 最低（运行时） | 高但封闭 | 封闭垂直产品 |
| 规划/子代理/文件系统 | 需自建 | **开箱内置** | 需自建 | 内置 | 内置（仅研究域） |
| 模型 | 任意 | **任意** | 任意 | 仅 Anthropic | 仅 OpenAI |
| 领域 | 通用 | **通用** | 通用 | 编码为主 | 研究报告 |
| 可定制深度 | 高 | **中高（换中间件）** | 最高 | 低 | 极低 |
| 长程任务表现 | 弱 | **强** | 取决于你写什么 | 强 | 强 |

一句话：**DeepAgents 填补的正是"薄 harness 不够聪明、裸 LangGraph 太费工程量、Claude Code 不可换模型/不可换领域"之间的空档。**

## 5. 局限性与采用建议

**⬜ 基准数据缺失（首要诚实声明）**：LangChain 曾发布 DeepAgents 相对朴素智能体在长程任务基准上的对比结论，方向为"harness 改进显著提升表现"；但**本次检索未能取回任何具体分数**（τ2-bench、金融类智能体基准的确切数值均属 C 级未获取）。**请勿在决策材料中引用任何未经复核的数字。** 另需注意：此类基准由框架作者自行测得，存在**作者自评偏差**，且不同 harness 的提示词预算往往不对等，横向比较需谨慎。

**工程局限**：
1. **成本与延迟**：长提示词 + 多轮规划 + 子代理 = token 消耗数倍于薄智能体；对秒级响应或高频调用场景可能不划算。
2. **过度脚手架风险**：简单任务上会出现"为规划而规划"——写一长串待办去做一件一步可完成的事，既慢又贵。
3. **委派失准**：子代理输出质量高度依赖任务描述自包含程度，这是最难调的部分，且失败模式隐蔽（结论看似完整）。
4. **提示词耦合**：内置提示词针对特定模型族调优，换模型后可能水土不服，需要重新调校。
5. **API 演进期**：参数与中间件构成仍在变化，升级存在破坏性变更风险。
6. **文件式记忆的检索粒度**（见 2.4）。

**采用建议**：
- **值得上**：任务步数多（>10）、上下文规模大（>窗口或接近）、需要并行探索、需要跨会话积累知识。
- **不建议**：单轮问答、固定流程（用工作流编排更可控）、对延迟敏感、任务边界清晰无需探索。
- **落地顺序**：先用默认配置跑通 → 用真实任务集测"规划是否被持续更新""子代理返回是否被采纳" → 再逐项裁剪中间件 → 最后决定后端与权限边界。

## 7. 结论

DeepAgents 的核心价值不在任何单点技术，而在于**把 2025 年以来在编码智能体与深度研究智能体上验证有效的四件套——显式规划、文件系统化的上下文管理、上下文隔离的子代理、文件式长期记忆——从专有产品中解耦出来，做成模型无关、领域无关、可逐项插拔的开源默认值**。

其中最具迁移价值的洞见是：**"上下文管理"与"长期记忆"其实是同一件事的两个时间尺度**——都把文件系统当作窗口之外的第二层存储；而**"详细系统提示词"之所以能负担得起，靠的是前缀稳定带来的缓存命中**。理解了这三条咬合关系，即便不使用 DeepAgents，也能在自己的 harness 中复现同等效果。
