# Demo 09 实操手册
## 一、为什么AI Agent需要Observability？
传统接口：
    请求
    ↓
    接口
    ↓
    响应
监控：
QPS
CPU
错误率
------------------------------------------------------------------------
AI Agent：
一次请求可能：
    用户问题
    ↓
    Planner Agent
    ↓
    LLM调用
    ↓
    Tool调用
    ↓
    RAG查询
    ↓
    再次LLM
    ↓
    最终回答
如果失败：
不知道：
-   哪一步慢？
-   哪个Prompt有问题？
-   哪个Tool失败？
-   Token消耗多少？
所以需要Trace。
------------------------------------------------------------------------
# 二、Trace是什么？
一次用户请求产生完整链路。
例如：
    trace_id:10001
    Step1:
    Agent
    耗时:
    200ms
    Step2:
    LLM
    耗时:
    3s
    tokens:
    2000
    Step3:
    Tool
    耗时:
    500ms
------------------------------------------------------------------------
# 三、核心指标
## 1. Latency
响应时间。
关注：
P95
P99
------------------------------------------------------------------------
## 2. Token
输入：
prompt token
输出：
completion token
用于：
成本计算。
------------------------------------------------------------------------
## 3. Tool调用
记录：
调用哪个工具
参数
结果
耗时
------------------------------------------------------------------------
## 4. Error
例如：
LLM timeout
Tool失败
RAG无结果
------------------------------------------------------------------------

# 六、面试回答
为什么Agent需要可观测？
因为Agent执行链路比传统API复杂，需要追踪模型调用、工具调用、上下文、Token消耗和错误原因，从而优化质量、成本和稳定性。
