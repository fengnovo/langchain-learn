# Demo 03 实操手册
## 一、为什么需要RAG？
大模型：
知道互联网公开知识。
但是不知道：
-   公司接口文档
-   内部规范
-   产品说明
-   私有代码
RAG解决：
给模型外挂一个知识库。
------------------------------------------------------------------------
# 二、整体流程
    知识文件
     ↓
    切片
     ↓
    Embedding
     ↓
    向量存储
    用户问题
     ↓
    问题Embedding
     ↓
    相似搜索
     ↓
    找到相关文本
     ↓
    加入Prompt
     ↓
    LLM回答
------------------------------------------------------------------------
# 三、运行
进入server：
``` bash
cd server
pnpm install
pnpm dev
```
配置：
.env
    LLM_API_KEY=xxx
    LLM_BASE_URL=xxx
------------------------------------------------------------------------
# 四、代码理解
## 1. Chunk
不要直接把整个文档发送给模型。
例如：
100页接口文档
拆：
    chunk1
    chunk2
    chunk3
原因：
-   控制token
-   提高检索准确率
------------------------------------------------------------------------
## 2. Embedding
文字：
    React Fiber是什么
转换：
    [0.123,0.543,...]
计算机可以比较语义距离。
------------------------------------------------------------------------
## 3. Retrieval
用户：
    如何发布项目？
转换向量。
搜索：
最接近的文档片段。
------------------------------------------------------------------------
## 4. Augmented Prompt
最终发送：
    你是助手。
    参考资料：
    xxx文档内容
    回答：
    用户问题
这就是：
Retrieval Augmented Generation。
------------------------------------------------------------------------
# 五、面试回答
问：
RAG为什么有效？
答：
RAG通过检索外部知识补充LLM上下文，让模型基于企业私有数据生成答案，同时避免重新训练模型。
