# 01 实操手册
## 目标
不要先研究所有源码。先完整跑一遍，再逐个替换 Mock。
---
## 第 1 步：检查环境
```bash
node -v
pnpm -v
docker --version
```
推荐 Node 22.12+。
---
## 第 2 步：复制环境变量
```bash
cp .env.example .env
```
第一次保持：
```env
MOCK_MODE=true
```
---
## 第 3 步：安装依赖
```bash
pnpm install
```
Monorepo 中 `workspace:*` 包会自动链接。
---
## 第 4 步：启动 API + Web
```bash
pnpm dev
```
打开：
```text
http://localhost:5173
```
输入：
```text
根据公司订单规范，开发订单查询模块。
```
点击执行。
---
## 第 5 步：观察输出
重点不是看“答案好不好”，而是看执行阶段：
```text
retrieve_context
mcp_context
planner
frontend
backend
qa
reviewer
harness
```
其中 frontend/backend/qa 是同一个 super-step 中的并行节点。
---
## 第 6 步：测试 MCP
```bash
pnpm mcp:inspect
```
打开 Inspector 后测试：
```text
search_code
```
参数：
```json
{
  "keyword": "order"
}
```
---
## 第 7 步：启动 PostgreSQL / Prometheus / Grafana
```bash
pnpm dev:infra
```
---
## 第 8 步：准备本地 qwen3.7-text-embedding
如果你装了 Ollama：
```bash
ollama pull qwen3.7-text-embedding
```
测试：
```bash
curl http://localhost:11434/api/embed \
  -d '{"model":"qwen3.7-text-embedding","input":"订单支付必须保证幂等"}'
```
---
## 第 9 步：切真实 RAG
`.env`：
```env
MOCK_MODE=false
EMBEDDING_API_KEY=ollama
EMBEDDING_BASE_URL=http://localhost:11434/v1
EMBEDDING_MODEL=qwen3.7-text-embedding
DATABASE_URL=postgresql://ai_native:ai_native@localhost:5432/ai_native
```
执行：
```bash
pnpm rag:seed
```
此命令会：
```text
mock-company 文档
 ↓
切片
 ↓
qwen3.7-text-embedding
 ↓
1024维向量
 ↓
PostgreSQL / pgvector
```
---
## 第 10 步：配置真实 LLM
例如你的提供方兼容 OpenAI API：
```env
LLM_API_KEY=xxx
LLM_BASE_URL=https://xxx/v1
LLM_MODEL=qwen3.8-max-0902```
重新：
```bash
pnpm dev
```
Planner / FE / BE / QA / Reviewer 会真正调用模型。
---
## 第 11 步：Prometheus
访问：
```text
http://localhost:3000/metrics
```
查看：
```text
agent_requests_total
agent_request_duration_seconds
agent_failures_total
agent_quality_score
```
---
## 第 12 步：Grafana
访问：
```text
http://localhost:3001
```
账号：
```text
admin / admin
```
Dashboard 已通过 provisioning 自动加载。
---
## 第 13 步：Langfuse
如果有 Langfuse：
```env
LANGFUSE_PUBLIC_KEY=...
LANGFUSE_SECRET_KEY=...
LANGFUSE_BASE_URL=...
```
Agent span 会被 OpenTelemetry processor 导出到 Langfuse。
---
## 第 14 步：Sentry / 飞书
配置：
```env
SENTRY_DSN=...
FEISHU_WEBHOOK_URL=...
```
发生未处理 Agent error 时：
```text
API
 ↓
Sentry.captureException
 ↓
Feishu webhook
```
飞书只是告警出口，不参与 Agent 主流程。
---
# 完成标准
当你能解释下面这条链，就算 Demo 10-B 真正吃透：
```text
Request
→ Context
→ Planner
→ fan-out
→ fan-in
→ Harness
→ Evaluation
→ Observability
```
