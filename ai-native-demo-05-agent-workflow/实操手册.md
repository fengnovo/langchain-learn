# Demo 05 实操手册
## 一、为什么需要 Workflow？
简单Agent：
```
用户
↓
LLM
↓
回答
```
复杂任务：
例如：
开发登录功能
需要：
- 分析需求
- 设计方案
- 写代码
- 检查代码
- 测试
所以需要 Workflow。
---
# 二、Workflow是什么？
Workflow：
提前定义任务执行流程。
例如：
```
需求
↓
Planner
↓
Coder
↓
Reviewer
↓
Tester
```
每个节点负责一个职责。
---
# 三、Agent角色
## Planner
负责：
拆任务。
输入：
开发用户登录
输出：
- 页面
- API
- 状态管理
- 测试
---
## Coder
负责：
根据方案生成代码。
---
## Reviewer
负责：
代码审查。
检查：
- 类型
- 性能
- 安全
---
## Tester
负责：
测试方案。
---
# 四、State是什么？
多个Agent之间需要共享数据。
例如：
```
state = {
 requirement,
 plan,
 code,
 review,
 test
}
```
每个节点读取和修改state。
---
# 五、fan-out / fan-in
高级Agent系统：
fan-out:
一个任务拆多个Agent并行。
```
           Planner
              |
    ------------------
    FE        BE       QA
```
fan-in:
汇总结果。
```
FE
BE
QA
 |
Reviewer
```
---
# 六、运行
进入：
```
cd agent
```
安装：
```
pnpm install
```
运行：
```
pnpm dev
```
观察：
每个Agent节点输出。
---
# 七、面试回答
什么是Agent Workflow？
回答：
Agent Workflow通过状态管理和节点编排，将复杂任务拆分成多个职责明确的Agent节点，通过有向流程控制任务执行，实现规划、执行、评审和验证。
