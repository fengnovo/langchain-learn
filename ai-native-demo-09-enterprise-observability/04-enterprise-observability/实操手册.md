# Demo09 企业级Agent Observability 实操手册
# 一、为什么需要企业级监控？
简单Demo：
    Agent执行
    ↓
    打印日志
生产环境：
每天：
100万个Agent请求。
需要知道：
-   哪个模型慢？
-   哪个Prompt效果差？
-   哪个工具失败？
-   花多少钱？
-   回答质量如何？
所以需要完整体系。
------------------------------------------------------------------------
# 二、OpenTelemetry
## 作用
统一采集Trace。
类似传统微服务链路追踪。
Agent：
    trace
     |
     |-- Planner
     |-- LLM
     |-- Tool
     |-- RAG
每一步都有：
-   时间
-   参数
-   状态
------------------------------------------------------------------------
# 三、Langfuse
专门面向LLM应用。
记录：
-   Prompt
-   Response
-   Token
-   Model
-   Cost
例如：
发现：
某Prompt导致回答质量下降。
可以直接查看历史。
------------------------------------------------------------------------
# 四、Prometheus
负责指标。
例如：
    agent_request_total
    llm_latency_seconds
    token_usage_total
    tool_error_total
关注：
数量和趋势。
------------------------------------------------------------------------
# 五、Grafana
展示数据。
例如Dashboard：
## Agent健康
-   QPS
-   P95耗时
-   错误率
## AI成本
-   Token
-   模型费用
## Tool
-   调用次数
-   失败率
------------------------------------------------------------------------
# 六、Sentry
负责异常。
例如：
Agent代码异常：
    MCP Server timeout
    RAG exception
    Tool参数错误
自动收集。
------------------------------------------------------------------------
# 七、飞书告警
生产：
不能天天看Dashboard。
需要主动通知。
例如：
    Agent错误率 > 5%
    ↓
    Sentry
    ↓
    Webhook
    ↓
    飞书机器人
    ↓
    研发收到告警
------------------------------------------------------------------------
# 八、Agent质量评分
AI不能只看成功。
需要评价：
## 1. Faithfulness
是否基于知识回答。
## 2. Relevance
是否回答问题。
## 3. Tool正确率
工具是否选对。
## 4. 用户反馈
综合评分。
------------------------------------------------------------------------
# 面试回答
企业Agent可观测体系包括：
Trace追踪、Metrics指标、Logs日志、Error监控和质量评估，通过OpenTelemetry采集链路，Langfuse管理LLM调用，Prometheus/Grafana监控运行指标，Sentry收集异常，并结合业务评价体系保证Agent稳定性和效果。
