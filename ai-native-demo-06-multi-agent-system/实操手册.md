# Demo 06 实操手册
## 一、为什么需要Multi-Agent？
单Agent：
    一个AI完成所有事情
    分析
    设计
    编码
    测试
问题：
-   上下文太长
-   角色混乱
-   任务复杂后质量下降
Multi-Agent：
让不同Agent承担不同职责。
------------------------------------------------------------------------
# 二、整体架构
    用户需求
    ↓
    Supervisor Agent
    ↓
    --------------------------------
    Frontend Agent
    Backend Agent
    QA Agent
    --------------------------------
    ↓
    Reviewer Agent
    ↓
    最终结果
------------------------------------------------------------------------
# 三、Supervisor Agent
Supervisor类似项目经理。
职责：
1.理解需求
2.拆分任务
3.分配Agent
4.收集结果
例如：
需求：
开发订单页面
拆：
FE:
页面和组件
BE:
接口
QA:
测试
------------------------------------------------------------------------
# 四、Agent通信
Agent之间不要传大量聊天。
推荐结构化协议。
例如：
``` json
{
 task:"开发订单页面",
 status:"completed",
 result:{
   files:[
     "Order.tsx"
   ]
 }
}
```
------------------------------------------------------------------------
# 五、fan-out
一个任务拆多个Agent。
                  Supervisor
                        |
           ----------------------
           FE       BE       QA
特点：
并行执行。
------------------------------------------------------------------------
# 六、fan-in
多个结果汇总。
    FE
    BE
    QA
     |
    Reviewer
Reviewer负责：
-   发现冲突
-   综合方案
-   输出最终结果
------------------------------------------------------------------------
# 七、运行
进入：
    multi-agent
安装：
    pnpm install
运行：
    pnpm dev
观察Agent执行过程。
------------------------------------------------------------------------
# 八、面试回答
什么是Multi-Agent？
回答：
Multi-Agent系统通过多个职责明确的Agent协作完成复杂任务，由Supervisor负责任务规划和调度，子Agent负责专业领域执行，通过结构化状态和通信协议完成结果聚合。
